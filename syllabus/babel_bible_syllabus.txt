================================================================================
                              THE ULTIMATE BABEL BIBLE
              Complete Master Syllabus for JS/TS Compilation & Transformation
================================================================================

NOTE: Babel is increasingly hidden under framework defaults (Next.js SWC, Vite
esbuild/SWC, Vitest esbuild). This bible covers the compiler pipeline, config,
presets/plugins, and custom transform authoring - plus when Babel is still the
right tool vs dead weight a migration should remove. Bundler-specific loader
wiring cross-links `webpack_bible_syllabus.txt` SECTION 4 and `vite_bible_syllabus.txt`
SECTION 8; test-runner transform config cross-links `jest_rtl_bible_syllabus.txt`.

--------------------------------------------------------------------------------
SECTION 1: WHY BABEL & THE COMPILER LANDSCAPE
--------------------------------------------------------------------------------
1.1 What Babel Does
    - Source-to-source AST transform             - "Compiler" not "bundler"; input JS/TS/JSX -> transformed JS, no linking/bundling.
    - Syntax support vs semantic transform             - Letting the parser understand new syntax vs actually rewriting it to older targets.

1.2 Babel vs SWC vs esbuild vs tsc
    - Why frameworks moved off Babel               - Rust/Go compiler speed (SWC, esbuild) vs Babel's JS-based traversal cost.
    - tsc's role                                       - Type-checking only by default; not a drop-in replacement for JSX/target transforms.
    - What Babel still uniquely offers                    - Largest plugin ecosystem, macros, arbitrary custom AST transforms, TC39 stage-X syntax.

1.3 Where Babel Still Matters in 2026
    - Custom plugin/macro pipelines             - styled-components/emotion codegen, babel-plugin-macros consumers.
    - Framework escape hatches                     - babelrc override support in Next.js/CRA-successors when a custom plugin is required.
    - Legacy/unusual targets                         - Browser matrices SWC/esbuild presets don't cover as granularly.
    - Codemods & tooling                                - jscodeshift and similar tools build on Babel's parser/traversal.


--------------------------------------------------------------------------------
SECTION 2: CORE COMPILATION PIPELINE
--------------------------------------------------------------------------------
2.1 Parse -> Transform -> Generate
    - @babel/parser                            - Produces an ESTree-derived AST from source text.
    - Visitor traversal                            - Plugins register node-type visitors; @babel/traverse walks and invokes them.
    - @babel/generator                               - AST back to source string + source map.

2.2 @babel/core Programmatic API
    - transformSync / transformAsync           - Embedding Babel in custom tooling (codemods, build scripts).
    - transformFileSync / transformFromAstSync     - File-based and pre-parsed-AST entry points.
    - Plugin/preset resolution order                 - How @babel/core merges config files, options, and caller metadata.

2.3 AST Fundamentals & Paths
    - Node types                               - Identifier, CallExpression, JSXElement, etc.; shared mental model with ESLint's ESTree.
    - Path objects                                - Wraps a node with traversal/mutation methods (parent, scope, context).
    - Scope tracking                                 - Binding resolution, reference counting, avoiding accidental shadowing in generated code.


--------------------------------------------------------------------------------
SECTION 3: CONFIGURATION SYSTEM
--------------------------------------------------------------------------------
3.1 Config File Forms
    - babel.config.js / .json / .cjs / .mjs    - Project-wide config; required for monorepo cross-package compilation.
    - .babelrc(.json)                             - File-relative config; package-scoped, does not apply across package boundaries by default.
    - package.json "babel" key                      - Inline config for small/single-package repos.

3.2 Config Resolution & Root (Monorepos)
    - root / rootMode                          - upward / upward-optional for monorepo root detection.
    - babelrcRoots                                - Opting specific packages into .babelrc resolution from a shared root.
    - Why this differs from ESLint's nearest-config     - Explicit root-based resolution vs directory-cascading discovery.

3.3 env-based Config
    - "env" key                                - Per BABEL_ENV/NODE_ENV config blocks (test/development/production).
    - Common test-only overrides                   - CommonJS module transform enabled only under "env.test" for Jest.

3.4 overrides
    - File-glob-scoped overrides                - Different plugins/presets for e.g. legacy/ vs src/ within one config.
    - test / exclude / include                    - Scoping precisely without maintaining multiple config files.

SECTION 4: PRESETS
--------------------------------------------------------------------------------
4.1 @babel/preset-env
    - browserslist targets                     - .browserslistrc driving which transforms/polyfills are actually included.
    - useBuiltIns: usage / entry / false           - Automatic polyfill injection strategies and their bundle-size tradeoffs.
    - corejs version pinning                         - Matching useBuiltIns to an installed core-js major version.
    - exclude / include                                - Forcing specific transforms on/off regardless of target inference.

4.2 @babel/preset-react
    - Classic vs automatic JSX runtime         - React.createElement calls vs jsx/jsxs imports from react/jsx-runtime.
    - development mode                            - jsx-dev-runtime, component stack warnings in dev builds.

4.3 @babel/preset-typescript
    - Type-stripping only                      - Removes type syntax; performs no type checking whatsoever.
    - isolatedModules / verbatimModuleSyntax        - Why type-only re-exports and const enums need TS-side flags to stay Babel-safe.

4.4 Framework-Bundled Presets
    - babel-preset-next                        - What Next.js composes under its own Babel path (when not on SWC).
    - metro-react-native-babel-preset               - React Native's Babel entry point.
    - Recognizing a vendored preset                    - Reading a framework's default config before adding a custom babel.config.js.


--------------------------------------------------------------------------------
SECTION 5: PLUGIN ECOSYSTEM
--------------------------------------------------------------------------------
5.1 Syntax vs Transform Plugins
    - @babel/plugin-syntax-*                   - Enables the parser to accept syntax; produces no output change alone.
    - @babel/plugin-transform-*                   - Actual codegen: rewrites syntax to a compatible form.

5.2 Stage-X / TC39 Proposal Plugins
    - Proposal lifecycle (stage 0-4)           - What "stage" signals about stability and spec risk.
    - Shipping stage-1/2 syntax in production        - Why this is a deliberate risk decision, not a default.

5.3 Common Ecosystem Plugins
    - babel-plugin-styled-components           - Displayname injection, minification-safe class names, SSR support.
    - @emotion/babel-plugin                       - Emotion's equivalent codegen plugin.
    - babel-plugin-module-resolver                  - Path alias resolution at compile time (vs bundler-level alias config).
    - babel-plugin-transform-imports                  - Per-import rewriting for tree-shaking legacy libraries.

5.4 Macros
    - babel-plugin-macros contract              - Compile-time code generation triggered by specially-named imports.
    - Common macro consumers                       - graphql.macro-style codegen; understanding what a macro expands to before debugging output.

SECTION 6: AUTHORING CUSTOM PLUGINS
--------------------------------------------------------------------------------
6.1 Visitor Pattern
    - enter / exit                             - Node-type visitor functions; traversal order and re-visiting on mutation.
    - path.traverse / path.skip                   - Nested traversal control; avoiding infinite loops on self-generated nodes.

6.2 Path & Scope APIs
    - path.replaceWith / insertBefore / remove - Core mutation primitives.
    - scope.generateUidIdentifier               - Collision-safe temp variable naming in generated code.
    - Binding lookups                              - scope.getBinding, reference counting before removing "unused" declarations.

6.3 @babel/types Builders
    - t.identifier / t.callExpression etc.     - Constructing valid AST nodes instead of hand-building plain objects.
    - Validators                                   - t.isX helpers for narrowing node types safely in a visitor.

6.4 Testing Plugins
    - babel-plugin-tester                      - Fixture-based valid/invalid transform test harness.
    - Snapshot-based transform tests               - Asserting generated output stays stable across plugin changes.

SECTION 7: TYPESCRIPT & JSX HANDLING
--------------------------------------------------------------------------------
7.1 Type-Stripping Semantics
    - Babel never checks types                 - tsc --noEmit (or typescript-eslint) remains mandatory alongside Babel for type safety.
    - Why builds can "pass" with type errors        - The gap between a successful Babel build and a type-correct one.

7.2 Babel-Unsupported TS Features
    - const enums                              - Require isolatedModules-safe alternatives (regular enums or object-as-const).
    - Legacy namespaces                              - Limited/no support; migration to ES modules.

7.3 Automatic JSX Runtime
    - jsxImportSource                          - Swapping the JSX factory (e.g. for Emotion's css prop) without touching every file.
    - No implicit React import                    - React 17+/19 automatic runtime removing `import React` boilerplate.
