SECTION 1: ROUTING FUNDAMENTALS (APP ROUTER)
--------------------------------------------------------------------------------
1.1 File Conventions
    1. page.js/tsx           - Defines a publicly routable UI segment.
    2. layout.js/tsx          - Shared, persistent UI wrapping child segments, preserves state across navigation.
    3. template.js/tsx         - Like layout but remounts on navigation (fresh state/animations per route).
    4. loading.js/tsx           - Automatic Suspense fallback boundary for a segment.
    5. error.js/tsx               - Automatic Error Boundary ('use client' required), reset() function.
    6. not-found.js/tsx            - Rendered on notFound() call or unmatched route.
    7. route.js/ts                  - Route Handlers (API endpoints) - mutually exclusive with page.js in same segment.


--------------------------------------------------------------------------------
SECTION 2: ADVANCED ROUTING PATTERNS
--------------------------------------------------------------------------------
2.1 Dynamic Segments
    - [id]                        - Single dynamic segment, exposed via params.
    - [...slug]                    - Catch-all segments (array of path parts).
    - [[...slug]]                    - Optional catch-all (matches the base route too).

2.2 Organizational & Advanced Segments
    - (groupName)                 - Route Groups - organize files without affecting the URL path.
    - @slot                         - Parallel Routes - render multiple pages in the same layout simultaneously.
    - (.)folder / (..)folder          - Intercepting Routes - render a route within the current layout (modals over feeds).
    - default.js                       - Fallback UI for parallel route slots on hard navigation.


--------------------------------------------------------------------------------
SECTION 3: RENDERING STRATEGIES
--------------------------------------------------------------------------------
3.1 Component Model
    - Server Components (default)    - Zero client JS, direct backend/data access, cannot use hooks/browser APIs.
    - Client Components ('use client') - Interactivity, hooks, browser APIs; boundary propagates to children.
    - Composition pattern              - Passing Server Components as children/props into Client Components.

3.2 Rendering Modes
    - Static Rendering (default)         - Pre-rendered at build time, cached, revalidated via ISR.
    - Dynamic Rendering                    - Rendered per-request (triggered by cookies(), headers(), searchParams, no-store fetch).
    - Streaming                             - Progressive HTML delivery via Suspense boundaries, improves TTFB.


--------------------------------------------------------------------------------
SECTION 4: DATA FETCHING
--------------------------------------------------------------------------------
4.1 The Extended fetch() API
    - cache: 'force-cache' vs 'no-store' - static vs dynamic data semantics; Next.js 15+ made 'no-store'-equivalent (uncached) the DEFAULT, reversing the Next 13/14 behavior where fetch() was cached by default.
    - next: { revalidate: N }               - Time-based ISR revalidation per fetch call.
    - next: { tags: [...] }                   - Tag-based on-demand revalidation.

4.2 Fetching Patterns
    - generateStaticParams()              - Pre-rendering dynamic routes at build time (replaces getStaticPaths).
    - Parallel data fetching                - Initiating multiple fetches before awaiting (avoiding waterfalls).
    - Sequential fetching                    - Intentional waterfalls when a fetch depends on prior data.
    - Request deduplication                   - Automatic memoization of identical fetch calls within a render pass.


--------------------------------------------------------------------------------
SECTION 5: SERVER ACTIONS & MUTATIONS
--------------------------------------------------------------------------------
5.1 Server Functions
    - 'use server'                        - Directive marking functions as server-executed, callable from client.
    - <form action={serverAction}>           - Progressive-enhancement-friendly native form binding.
    - Programmatic invocation                  - Calling actions inside startTransition, onClick handlers.

5.2 Revalidation & Optimistic UI
    - revalidatePath() / revalidateTag()     - Purging cache entries after a mutation.
    - useActionState / useFormStatus / useOptimistic - React 19 hooks wired into the Server Action lifecycle.


--------------------------------------------------------------------------------
SECTION 6: CACHING ARCHITECTURE (THE FOUR LAYERS)
--------------------------------------------------------------------------------
6.1 Layer Breakdown
    1. Request Memoization      - Per-render dedup of identical fetch() calls (React cache()).
    2. Data Cache                 - Persistent cross-request/cross-deployment fetch cache, tag/time-based invalidation.
    3. Full Route Cache            - Static HTML + RSC payload cached at build time per route.
    4. Router Cache (Client)        - In-browser cache of visited/prefetched RSC payloads for instant back/forward nav.

    - opengraph-image.tsx / icon.tsx          - File-convention-based dynamic image generation.

SECTION 12: RENDERING RUNTIMES
--------------------------------------------------------------------------------
12.1 Runtime Selection
    - Node.js runtime (default)          - Full Node API access, larger cold start.
    - Edge runtime                          - V8 isolates, low latency, restricted API surface (export const runtime = 'edge').

SECTION 13: CONFIGURATION (next.config.js)
--------------------------------------------------------------------------------
13.1 Key Options
    - redirects() / rewrites() / headers()    - URL and header manipulation at the framework level.
    - images config                              - Allowed remote domains/patterns, formats (avif/webp).
    - output: 'standalone' | 'export'              - Minimal server bundle vs fully static export.

SECTION 14: DEPLOYMENT & BUILD
--------------------------------------------------------------------------------
14.1 Build Lifecycle
    - next build                              - Compiles, prerenders static routes, generates route manifest.
    - Incremental Static Regeneration (ISR)     - On-demand and time-based re-generation of static pages post-deploy.
    - Output modes                               - standalone (self-contained Node server) vs export (static HTML only).

SECTION 15: ADVANCED PATTERNS
--------------------------------------------------------------------------------
15.1 Composition & Performance
    - Server/Client composition boundaries      - Minimizing client bundle by pushing 'use client' as deep as possible.
    - Streaming with loading.tsx + Suspense       - Granular per-section loading states.
    - Error boundary hierarchy                      - error.js vs global-error.js scoping.
    - Parallel data fetching across nested layouts to avoid request waterfalls.
