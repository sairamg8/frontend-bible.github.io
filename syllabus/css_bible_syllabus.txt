DOCUMENTATION STANDARD FOR EVERY CONCEPT:
Each concept must be documented with 4 mandatory sections:
  1. Concept & Under-the-Hood Browser Mechanics (cascade, layout, paint, composite)
  2. Real-World Engineering Scenario (Production Use Case)
  3. Production-Grade Code Example (vanilla CSS; React/CSS Modules notes where relevant)
  4. Senior Engineer Edge Cases & Pitfalls (specificity wars, overflow bugs, a11y, subpixel)

NOTE: This bible catalogs the CSS *language and layout engines* (especially
Flexbox + Grid + modern layout tricks). Styling *architecture* choices
(Tailwind vs CSS Modules vs CSS-in-JS, design tokens strategy) live in
`frontend_architecture_bible_syllabus.txt` SECTION 6 - do not duplicate those
here; cross-link when a concept depends on architecture context.
